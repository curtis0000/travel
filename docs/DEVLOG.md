# DEVLOG（只留決策、放棄的路、坑；新段加在最下面）

## 2026-09-24 起步

- 純前端讀 md 而非 static site generator：使用者非工程背景，「丟 md 進資料夾」是唯一能接受的維護方式。
- 時間軸採「等高但由內容撐開」而非成比例：使用者要省空間，且明確要求文字不能被截。時間長短靠標示的時間與時長文字表達。
- 地點抓法選「冒號前文字自動抓」而非 `[[地點]]` 標記：少打字優先，搜錯再補標記（已在 CLAUDE.md 預留）。
- 移動資訊獨立成 `→` 行：原本混在停留那行的文字裡，parser 抓不出時長，也畫不出連接條。
- 否決 Netlify Drop：每次整包重拖；GitHub Pages 改一個 md 上傳即可，且 gh 已登入。

## 2026-09-24 步驟 1：時間軸

- 時間軸用三欄 grid（時間｜軌道｜內容）而非絕對定位：色塊高度由內容撐開，不會截字，也不用算像素。
- 跨午夜：結束 < 開始就 +24h；下一站開始比游標早超過 12 小時也視為隔天（處理 22:30–01:00 之後的 02:00）。
- 移動時長加總該行所有「N 分」「N 小時」：Skyliner 40 分＋山手線 15 分要算 55 分，只抓第一個會少算。
- 備註預設收合，「注意：」另外做成常駐警示框：旅途中最需要一眼看到的是提醒，不是店家細節。
- 坑：Chrome 擴充套件 resize_window 縮不到 430px，改用 JS 把 main 限寬 358px 模擬手機。

## 2026-09-24 步驟 2：總覽分頁、地圖、待辦

- 總覽獨立成分頁（用戶要求）：原本排在時間軸後面，要捲很久才看得到；當第一個分頁後，非旅程期間預設就停在總覽。
- 待辦勾選的 key 用「條目文字」而非序號：md 增刪一行不會讓其他項目的勾選狀態錯位；改文字才會重置，可接受。
- 表格轉卡片用 CSS + data-label 而非改寫 marked 輸出：marked 的 HTML 原封不動，之後升級不會壞。
- 地圖搜尋字串直接用地點名，不加城市：跨城市行程（東京＋越後湯澤）加了反而搜錯。
- 坑：測淺色模式時 document.styleSheets[0] 是 Google Fonts 的跨域樣式表，讀 cssRules 會丟 SecurityError；要抓 head 裡自己的 style。

## 2026-09-24 上線 + 地點路線工具

- 部署用 gh repo create --push + gh api 開 Pages，不用 Actions：純靜態檔，main 分支根目錄直接服務，加 .nojekyll 避免 Jekyll 處理。
- 路線用 Google Maps Directions URL（api=1）而非嵌入地圖：不用 API key、手機會直接跳 Google Maps app。限制是最多 10 點，且大眾運輸模式不吃中途點。
- 地點只從時間軸的停留項目抓，不掃全文：全文找地名要靠猜，寧可少列也不列錯；沒排時間的餐廳等排進時間軸再出現。
- 地點勾選順序不存 localStorage：每次規劃路線都是新的組合，存了反而要先清。

## 2026-09-24 視覺改版：雜誌編輯風

- 業主訪談三題：調性＝雜誌編輯風、情境＝旅途中優先、色＝固定淺色。據此拿掉深色模式與卡片陰影，改細線＋襯線大標。
- 坑：`.md h2` 的 display:block 蓋掉 `.panel h2` 的 flex（同權重、後宣告贏），DAY 刊頭號不換行；改成只針對 `#o h2`。
- 標題加 `word-break: keep-all`：中文標題才會在空格處斷行，不會把「跨年」拆成兩行。

## 2026-09-24 視覺改版第二版：雪影藍路線圖

- 業主否決第一版：「討厭奶茶底色，審美疲勞」。impeccable skill 也點名米色底＋襯線＋等寬小標是 2026 年 AI 生成的飽和套路，整個方向作廢。
- 新概念找實體參照：雪地影子是藍紫色、東京地鐵路線圖。純白＝雪、靛藍＝影子，時間軸畫成路線＋站。
- 字體：CJK 只能用 Noto Sans TC（改用 900 重量做標題），數字換 Bricolage Grotesque（wdth 88），避開 Inter／DM Mono 等反射性選擇。
- 底色用純 #fff 而非「微暖白」：warmth 交給品牌色與字重，底色一加暖就回到奶茶。
